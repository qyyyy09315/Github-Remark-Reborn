## 2026-10-17 · 项目现状审计

**背景**：接手重制版代码，需要评估可维护性、安全性与后续演进方向。

**发现的关键问题**：
1. 鉴权形同虚设：以 GitHub 用户名作为 `token` 调用云端接口，任何人可篡改他人备注。
2. 后端 `server/db.js` 硬编码 Linux 全局模块路径，跨环境必然启动失败。
3. 内容脚本直接读写宿主 `github.com` 的 `localStorage`，污染宿主存储且与扩展 Options 存储隔离。
4. 渲染期间每个用户名触发一次 HTTP 请求，列表页存在 N+1 请求风暴。
5. 未备注用户在页面上没有任何添加入口，功能闭环缺失。
6. 弹窗/设置页依赖外部 Bootstrap CDN，不符合 Manifest V3 商店审核要求。

**结论**：确定「存储层解耦 + 本地优先渲染 + 自包含 UI」的重构方向。

## 2026-10-19 · v1.0.0 架构重构与视觉升级

**实现内容**：
- 新增 `storage.js`：统一包装 `chrome.storage.sync`（优先）与 `chrome.storage.local`（兜底），提供备注增删改查、JSON 导入导出、跨标签页变更广播。
- `manifest.json`：改为声明式 `content_scripts` 注入，权限收敛为 `storage` + `contextMenus`，移除错误的 `devtools_page`。
- `ghremark.js`：内存 Map 渲染、个人主页常驻入口、列表页悬停添加入口、DOM 防抖扫描、Turbo 导航适配、SVG 图标内联。
- `popup.html/js`、`options.html/js`：纯原生 CSS 重写，新增统计、搜索、就地编辑与备份中心。
- `server/`：补齐 `package.json`，改用标准依赖路径，`async/await` 重写并增加统一异常处理。

**关键决策**：
- 放弃依赖公共云接口作为主链路，改用浏览器原生同步，避免隐私与鉴权风险。
- 徽章渲染只读取内存缓存，网络请求仅用于同步写入，渲染阶段零 IO。

**踩坑与修复**：
- GitHub 在浅色模式下同样会输出 `data-dark-theme="dark"`（用于标记暗色偏好），导致早期 CSS 误命中暗色分支，徽章文字变浅发白。最终严格以 `html[data-color-mode="dark"]` 作为唯一判据。
- GitHub 关注列表中头像本身也是 `a[data-hovercard-type="user"]`，早期会给头像再挂一次徽章。改为过滤包含 `img` / `.avatar` 的链接。

**发布**：`manifest.json` 版本置为 `1.0.0`，打包 `GithubRemarkReborn-v1.0.0.zip`，创建 GitHub Release 并附发布说明。

## 2026-10-21 · 修复悬停徽章消失问题

**现象**：鼠标移到备注徽章上，徽章立即消失（或高频闪烁）。

**根因分析**：
1. 旧实现把 ✎/✕ 按钮渲染在徽章内部，默认 `display: none`，`:hover` 时变为 `inline-flex`。
2. 展开按钮使徽章宽度瞬间增加约 40px，触发父容器（GitHub 列表的 flex/table 布局）重排，徽章被推离指针位置。
3. 指针离开徽章立即触发 `mouseleave`，按钮收起、徽章变窄，指针又重新落在徽章上，形成 `mouseenter/mouseleave` 高频循环——视觉表现就是「标签消失」。
4. `:hover` 上的 `translateY(-0.5px)` 产生亚像素位移，进一步加剧边缘命中抖动。
5. 另一个隐患：`ghrk-processed-link` 标记一旦写入，若 GitHub 局部重绘移除了徽章节点但保留了链接节点，扫描会永久跳过该用户。

**解决方案**：
- 操作按钮改为挂载在 `document.body` 的 **固定定位悬浮操作条**（`position: fixed`，`z-index: 2147483000`），完全不参与父容器布局，徽章尺寸恒定。
- 悬浮条默认出现在徽章右侧并垂直居中；右侧/底部空间不足时自动翻转到下方或上方，避免视口溢出。
- 指针从徽章移向操作条时，`mouseleave` 只启动 180ms 延迟收起，指针进入操作条立即取消，消除间隙闪烁。
- 滚动、缩放、关闭插件、删除备注、跨页同步时主动收起悬浮条。
- 移除 `:hover` 的 `translateY` 位移，仅保留底色与描边变化。
- 扫描逻辑改为「存在性校验」：即使链接带有 `ghrk-processed-link`，只要徽章/添加按钮节点已不存在，就重新补挂，实现自愈。

**验证**：
- `node -c ghremark.js` 语法校验通过。
- 使用 jsdom 搭建 GitHub 列表结构（已备注用户 + 未备注用户 + 头像链接），模拟真实事件完成 17 项回归断言，**全部通过**：
  - 已备注用户渲染徽章，头像链接不重复挂载，每行仅一个徽章；
  - 徽章内部不再包含任何按钮节点，尺寸恒定；
  - `mouseenter` 后悬浮操作条出现在 `body` 下（`display: inline-flex`），徽章保持连接；
  - `mouseleave` 260ms 后操作条收起，**徽章仍然存在**（核心回归点）；
  - 通过悬浮条编辑：输入框出现 → 回车保存 → 徽章文本与存储同步更新；
  - 通过悬浮条删除：徽章移除、存储清除、该用户重新出现「+ 备注」入口。
- 代码检索确认旧 `.ghrk-tools` / `.ghrk-btn-tool` 引用已全部清除。

**仍需人工确认（浏览器真机）**：
- [ ] Edge 与 Chrome 中在关注列表悬停徽章 3 秒以上，无消失、无闪烁。
- [ ] 页面右侧边缘的徽章，悬浮条自动翻转到下方且不被视口裁切。
- [ ] 深色模式下悬浮条背景、边框与图标配色可读。
- [ ] GitHub 原生 Hovercard 弹出时，操作条不与用户卡片严重重叠。

## 2026-10-21 · 原创图标接入

**背景**：旧图标使用 GitHub 官方 Logo，存在商店商标审核风险，同时 16/32/48 均复用同一张小图，高分屏偏糊。

**处理过程**：
1. 设计规格收敛为「深蓝渐变圆角底 + 纯白吊牌」，并实测 16px：带铅笔的装饰版会退化成白色短线，因此工具栏只保留吊牌剪影。
2. 用户提供 1254×1254 AI 生成图（RGB、白色背景）。用四角洪水填充（阈值 28）去除白色外底，保留内部吊牌；确认吊牌中心不透明、圆角外缘 alpha=0。
3. 裁切到图标边界后，采用**预乘 alpha + LANCZOS** 缩放，避免透明边缘出现黑边，输出 16/32/48/128 与 300×300 商店 Logo。
4. `manifest.json` 的 `icons` 与 `action.default_icon` 全部改为新图标；弹窗、设置页、头像加载失败兜底、README 头图同步替换。

**验证**：
- 16/32/48/64 四档在浅色与深色背景上均能清晰识别为吊牌；
- 各尺寸 PNG 为 RGBA，四角 alpha=0；
- `manifest.json` 可正常解析，图标路径全部存在；
- jsdom 交互回归 17 项全部通过，未影响备注功能。

**注意**：`images/github.png`、`github_128.gif`、`github_512.png`、`Remark setting.jpg` 已不再被引用，但暂未删除；打包商店 zip 时应排除。

## 2026-10-23 · 本人识别（自己不需要备注）

**需求**：用户反馈浏览自己主页时出现「+ 添加备注」/「我」徽章不合逻辑——自己无需备注，或备注"我"也无意义。

**实现**：
- 新增 `isSelfUser()`：读取 `meta[name="user-login"]` 与目标用户名做大小写不敏感比对。
- `renderProfileSection()`：检测到当前主页属于本人时，不渲染任何组件并移除已有容器。
- 全站扫描：指向登录用户本人的链接不挂徽章、不挂「+ 备注」入口，且主动清理历史遗留节点（覆盖用户此前给自己加过备注的情况）。

**验证**：jsdom 回归扩充至 20 项断言，全部通过——自己主页无备注组件、指向自己的链接无徽章无入口，原有徽章渲染、悬浮操作条、编辑/删除流程均不受影响。

## 2026-10-23 · 存储切换为纯本地

**背景**：用户询问「云同步是否真实」。结论：真实——此前的 `chrome.storage.sync` 通过浏览器账号（Edge/Google）同步，不经过自建服务器；但存在硬性配额（总量 100KB、单项 8KB、最多 512 项），且实现把全部备注放在单个键里，备注超过百余条后写入会静默失败并退化为本地，同步形同失效；同时依赖用户登录浏览器账号并开启扩展同步。

**决策**：按用户要求改为纯本地存储。`chrome.storage.local` 在 MV3 下默认配额约 10MB，无单键 8KB 限制，不依赖任何账号。跨设备迁移统一走控制台的 JSON 导出/导入。保留一次性迁移兜底：首次读取时若本地为空而 sync 存有旧数据，自动搬迁到本地（此前版本是 sync+local 双写，多数用户本地已有完整副本，迁移只是保险）。

**影响与验证**：
- 多标签页实时联动不受影响（`chrome.storage.onChanged` 对 local 区域同样广播）；
- `options.html` 提示文案、README 徽章与特性表、CHANGELOG 同步更新；
- jsdom 回归 20 项断言全部通过；
- 待真机确认：旧版本升级用户首次打开页面后，备注应完整出现在本地（可从设置页数量核对）。
